# 바른결 — AI 기반 실시간 자세 교정 및 자세 습관 관리 앱

완성된 웹앱 전체 코드는 `index.html`에 있습니다. HTML·CSS·JavaScript가 모두 들어 있으며 빌드 도구, API 키, 데이터베이스 또는 유료 AI 서비스가 필요하지 않습니다. 외부 CDN과 공개 모델을 다운로드하기 위한 인터넷 연결은 필요합니다. `microbit-makecode.js`는 마이크로비트에 업로드하는 별도 프로그램입니다.

**먼저 확인할 점:** 2026년 11월 3일 실제 기본 모델의 메타데이터와 브라우저 로딩 결과에서 클래스는 **`Class 1` 하나**였습니다. 요청문의 소문자 `class 1`로 변경하지 않았습니다. 클래스가 하나뿐인 분류기는 다른 자세를 구별할 수 없고 점수가 항상 높을 수 있습니다. 앱은 이 경우 클래스 확률만 표시하고 자세 판정을 제한하며, 시간을 ‘인식 불가능’으로 기록합니다. 좋은 자세 비율은 `—`가 됩니다. 전체 교정·알림 흐름을 시험하려면 좋은 자세와 비교용 자세 등 **최소 두 개의 클래스를 충분히 학습한 Pose Model**을 넣어 주세요. 여러 클래스를 추가해도 앱이나 마이크로비트 코드를 다시 작성할 필요는 없습니다.

## 1. 프로젝트 전체 작동 원리

1. 사용자가 카메라 시작을 누르면 기본 또는 지정한 Teachable Machine **포즈 모델**을 불러옵니다. 설정에서 미리 불러올 수도 있습니다.
2. 카메라 프레임을 400×400 정사각형으로 처리합니다. 기본 좌우 반전은 Teachable Machine의 기본 학습 화면에 맞춥니다.
3. `model.estimatePose()`로 관절점과 포즈 분류 입력을 얻고, `model.predict()`로 실제 클래스별 확률을 계산합니다. 이미지 분류 라이브러리를 사용하지 않습니다.
4. 머리, 양쪽 어깨, 상체 관절이 충분히 보이는지 먼저 확인합니다. 포즈 전체 점수 0.2 이상, 주요 관절 점수 0.45 이상 등의 휴리스틱을 사용합니다. 이는 완벽한 사람 검출 보장이 아니므로 실제 촬영 환경에서 조정·검증해야 합니다.
5. 최근 1.2초 안의 최대 5프레임 확률을 평균합니다. 최소 3프레임과 0.8초의 같은 상태가 모여야 좋은 자세 또는 확인 필요 상태로 확정합니다. 안정화 중인 시간도 인식 불가능으로 처리합니다.
6. 좋은 자세 클래스의 평균 확률이 기본 80% 이상이면 초록색 ‘좋은 자세’, 그보다 낮으면 노란색 ‘자세 확인 필요’로 표시합니다. 낮은 확률을 나쁜 자세로 확정하지 않습니다. 사람이 보이지 않거나 단일 클래스 모델이면 회색 ‘인식 불가능’입니다.
7. 확인 필요 상태가 기본 10초 연속되면 주황색 ‘주의 상태 지속’을 표시합니다. 알림을 켜 두었다면 화면 알림, 알림 시각 기록, 선택적 소리·LED가 동작합니다. 같은 구간은 한 번만 알립니다. 좋은 자세로 돌아오면 알림 제한을 해제합니다. 인식 불가능이나 일시정지는 연속 시간을 끊지만, 이미 발생한 알림의 제한은 좋은 자세로 돌아올 때 해제합니다.
8. 마이크로비트가 연결되어 있으면 안정화된 클래스의 원문과 앱의 상태를 구별해 USB 시리얼로 전송합니다. 장치가 없어도 분석과 저장은 동작합니다.
9. 종료하면 시간과 알림 시각을 localStorage에 저장합니다. 매 5초와 탭 숨김 시 임시 저장하며, 갑작스러운 종료 후에는 마지막 임시 저장 지점까지 복구합니다. 영상·관절 좌표는 저장하거나 업로드하지 않습니다.
10. 날짜별 가중 통계와 최초·최근 측정을 비교하고, 출처가 연결된 자세 가이드를 제공합니다.

분석은 이전 분석이 끝난 뒤 최소 125ms를 두고 다음 프레임을 처리합니다. 분석 요청이 겹치지 않습니다. 1.5초 넘게 새로운 결과가 없으면 이전 좋은 자세를 계속 누적하지 않으며, 긴 정지·절전 공백은 인식 불가능으로 처리합니다.

## 2. 전체 웹앱 코드

**`index.html`이 생략 없는 전체 코드입니다.** 이 파일 하나를 복사해 사용할 수 있습니다. 다른 프로젝트 파일을 참조하지 않으며 아이콘, 그림, 스타일, 화면, 기능이 모두 들어 있습니다.

포함 화면은 대시보드, 실시간 자세 분석, 자세 기록, 자세 변화 통계, 올바른 자세 가이드, 설정입니다. 기록이 없을 때 예시 기록을 만들거나 예시 수치를 실제 데이터처럼 표시하지 않습니다. 그래프는 외부 차트 라이브러리 없이 SVG로 생성하며 통계 수치 표도 제공합니다.

파일을 직접 더블클릭해서 화면과 저장 기록을 볼 수 있지만, `file://` 환경의 카메라·시리얼·저장소 동작은 브라우저마다 다릅니다. **실제 사용은 데스크톱 Chrome에서 HTTPS 또는 localhost로 실행**해 주세요.

로컬 실행 예시(이미 Node.js가 설치되어 있을 때):

```powershell
cd "압축을 푼 폴더"
npx --yes http-server . -a 127.0.0.1 -p 8080 -c-1
```

Chrome에서 `http://127.0.0.1:8080`을 여세요. 또는 아래 Netlify 방식으로 설치 없이 배포할 수 있습니다. 측정은 한 탭만 가능하도록 Web Locks API로 잠급니다. 탭을 숨기면 자동 일시정지하며, 돌아와서 ‘다시 시작’을 눌러야 합니다. 일시정지 중 카메라 영상 재생은 멈추지만 장치는 유지됩니다. **종료 및 저장**을 누르면 카메라 트랙을 해제합니다.

## 3. 마이크로비트 코드

**`microbit-makecode.js`가 V1.5용 MakeCode JavaScript 전체 코드입니다.** 외부 부품, 서보, V2 전용 기능을 사용하지 않습니다.

통신은 115200bps, UTF-8, 실제 LF(`\n`) 줄바꿈을 사용합니다. 원래 클래스 문자열을 A/B/C 등으로 바꾸지 않습니다. 클래스와 제어 문자열이 우연히 같아도 충돌하지 않도록 **헤더와 본문 두 줄**을 하나의 프레임으로 보냅니다.

```text
FRAME:CLASS
Class 1
```

다음은 내부 제어 상태입니다.

```text
FRAME:STATUS
STATUS:GOOD

FRAME:STATUS
STATUS:CHECK

FRAME:STATUS
STATUS:WARNING

FRAME:STATUS
STATUS:UNKNOWN
```

위의 빈 줄은 예시를 구분하기 위한 것으로 실제 전송에는 포함하지 않습니다. 예를 들어 첫 클래스 프레임의 실제 바이트는 `FRAME:CLASS\nClass 1\n`입니다. 사용자가 지정한 좋은 자세 클래스는 다음 설정 프레임으로 전달됩니다.

```text
FRAME:GOODCLASS
Class 1
```

| 수신 상태 | LED |
|---|---|
| 좋은 자세 / `STATUS:GOOD` | 체크 |
| 확인 중 / `STATUS:CHECK` | 물음표 |
| 지속 주의 / `STATUS:WARNING` | 느낌표 |
| 미인식·일시정지·종료 / `STATUS:UNKNOWN` | 가운데 가로선 |

펌웨어는 클래스 원문을 보존해 `ACK:CLASS:원문`으로 응답합니다. `STATUS:WARNING`이라는 이름의 AI 클래스도 `FRAME:CLASS` 다음 줄이면 제어 명령이 되지 않습니다. 프레임이 2초 안에 완성되지 않으면 초기화합니다. V1.5 수신 버퍼와 줄 구분의 한계 때문에 **클래스 이름에 줄바꿈이 있거나 UTF-8 96바이트를 초과하면 해당 이름의 전송만 제한**하고 이유를 통신 로그에 표시합니다. AI 화면·기록은 계속 동작하며 이름을 임의로 축약하지 않습니다.

웹앱은 연속 동일 프레임을 생략하고 전송 사이를 최소 450ms로 제한합니다. 포트 읽기·쓰기 잠금을 해제한 후 닫고, USB 연결 해제를 감지합니다. 종료 시 대기 프레임을 한 번 보낸 뒤 자동 자세 전송을 중단합니다. 소리·장치 테스트 버튼은 설정에 있습니다.

## 4. 마이크로비트 연결 방법

1. [Microsoft MakeCode](https://makecode.microbit.org/)에서 새 프로젝트를 만듭니다.
2. 위쪽 **JavaScript** 편집기를 선택하고 기본 코드를 지운 뒤 `microbit-makecode.js` 전체를 붙여 넣습니다.
3. 데이터 전송을 지원하는 USB 케이블로 마이크로비트 V1.5를 연결합니다.
4. MakeCode에서 다운로드한 `.hex` 파일을 **MICROBIT** 드라이브에 복사합니다. 복사 중 표시등이 끝날 때까지 기다립니다.
5. MakeCode의 장치 연결, 시리얼 모니터 및 다른 시리얼 프로그램을 닫습니다. 같은 포트를 동시에 사용하면 열리지 않을 수 있습니다.
6. HTTPS 또는 localhost 웹앱을 **데스크톱 Chrome**에서 엽니다. 설정 → 장치 연결을 누르고 해당 마이크로비트 시리얼 포트를 선택합니다.
7. ‘연결됨 · 115200’과 송수신 로그를 확인합니다. 수동 전송에서 정상·주의·대기를 각각 보내 LED와 ACK를 확인합니다. 실제 측정 중에는 일시정지한 뒤 수동 테스트를 사용하세요.
8. 측정을 시작하면 선택된 좋은 자세 클래스 매핑과 안정화된 결과가 자동 전송됩니다.
9. 사용을 마치면 측정을 종료한 뒤 연결 해제를 누릅니다. 마이크로비트가 연결되지 않아도 측정과 기록은 사용할 수 있습니다.

참고: [MakeCode Serial API](https://makecode.microbit.org/reference/serial), [줄바꿈 수신 이벤트](https://makecode.microbit.org/reference/serial/on-data-received), [Chrome Web Serial 공식 안내](https://developer.chrome.com/docs/capabilities/serial).

## 5. Teachable Machine 연결 방법

1. [Teachable Machine](https://teachablemachine.withgoogle.com/)에서 **Pose Project**를 사용합니다. Image Project 또는 Audio Project 모델은 사용할 수 없습니다.
2. 기본 URL은 `https://teachablemachine.withgoogle.com/models/HU67qJ2Mw/`입니다. 설정 → 모델 불러오기를 누르면 모델의 모든 실제 클래스 이름을 자동으로 읽습니다.
3. 현재 기본 모델에는 `Class 1` 하나만 있으므로, 정상 자세와 비교용 자세 등을 추가로 학습하고 모델을 업로드한 URL로 교체하세요. 조명·거리·옷·여러 사람 등 학습 조건도 다양하게 준비하세요.
4. 새 URL을 붙여 넣고 모델 불러오기를 누릅니다. 다른 모델에서는 ‘좋은 자세로 사용할 클래스’를 직접 지정합니다. 클래스 이름 자체는 변경되지 않습니다.
5. 좋은 자세 인식 기준(기본 80%)과 알림 기준 시간(기본 10초)을 정합니다. 두 값과 모델·카메라·반전은 측정 중 변경하지 못하도록 잠깁니다.
6. 실시간 분석으로 이동해 카메라 시작을 누르고 권한을 허용합니다. 얼굴과 양쪽 어깨, 상체가 정사각형 프레임 안에 보이도록 조정합니다.
7. 화면의 클래스별 확률, 안정화된 상태, 각 상태의 누적 시간을 확인합니다. 좋은 자세 클래스의 확률이 낮아도 질환이나 나쁜 자세를 확정하지 않습니다.
8. 측정 종료 후 기록과 통계를 확인합니다. 모델 URL·클래스·인식 기준이 다른 최초/최근 기록은 비교 주의 문구가 표시됩니다.

공식 구현 참고: [Google Teachable Machine Pose Library](https://github.com/googlecreativelab/teachablemachine-community/tree/master/libraries/pose). 공식 안내의 호환 조합인 TensorFlow.js 1.3.1과 `@teachablemachine/pose` 0.8.3을 명시적으로 불러옵니다. 오래된 모델용 라이브러리이므로 버전만 임의로 최신으로 바꾸면 호환성이 달라질 수 있습니다.

## 6. Netlify 배포 방법

이 결과물은 사용자가 코드를 받아 직접 실행·배포할 수 있도록 만든 로컬 프로젝트입니다. Netlify 계정에 로그인하거나 외부 사이트에 대신 게시하지 않았습니다.

1. ZIP을 압축 해제합니다. **`index.html`이 폴더 바로 아래**에 있는지 확인합니다.
2. [Netlify Drop](https://app.netlify.com/drop) 또는 Netlify 대시보드의 수동 배포 화면을 엽니다. 계정이 필요하면 본인 계정으로 진행합니다.
3. `index.html`을 담은 폴더를 업로드 영역에 끌어 놓습니다. 빌드 명령·백엔드·환경 변수 설정은 필요하지 않습니다.
4. 배포가 끝나면 발급된 `https://…netlify.app` 주소를 데스크톱 Chrome에서 엽니다.
5. 새 주소에서 카메라 권한과 시리얼 포트 권한을 허용한 뒤 모델·카메라·LED를 확인합니다.
6. 수정 시 같은 프로젝트의 수동 배포 영역에 최신 폴더를 업로드합니다.

로컬 주소와 Netlify 주소는 서로 다른 저장 공간입니다. 기존 기록을 옮기려면 이전 주소에서 **JSON 백업**을 받고 새 주소에서 **백업 복원**을 실행하세요. CSV는 열람용이며 앱 복원 형식은 JSON입니다. 앱은 API 키나 유료 서비스를 요구하지 않습니다. 호스팅 서비스의 현재 요금·사용 한도는 Netlify 계정에서 확인하세요.

공식 참고: [Netlify 수동 드래그 앤드 드롭 배포](https://docs.netlify.com/deploy/create-deploys/#deploy-with-drag-and-drop).

## 7. 데이터 저장 및 통계 기능

### 저장하는 정보

- 고유 측정 ID, 시작·종료 시각(ISO), 전체·좋은 자세·확인 필요·인식 불가능 시간(밀리초)
- 알림 횟수와 각 알림 시각
- 날짜별 시간 버킷(자정을 지나는 측정을 나누기 위한 정보)
- 사용한 모델 URL, 전체 클래스 목록, 좋은 자세 클래스, 인식 기준, 알림 기준 시간, 좌우 반전 설정

한 측정은 같은 ID로 갱신하므로 저장을 재시도해도 중복되지 않습니다. 같은 날 여러 번 측정한 기록은 각각 보존하고 날짜별로 합산합니다. 자정을 지나는 측정은 날짜별 실제 시간으로 나누고, 알림은 발생한 날짜에 더합니다. 날짜별 측정 횟수는 그 날짜에 시간이 기록된 측정 수입니다. 탭을 숨긴 시간과 명시적 일시정지는 측정 시간에서 제외합니다.

localStorage 키는 `bareungyeol.records.v1`, `bareungyeol.settings.v1`, `bareungyeol.active.v1`입니다. 마지막 키는 진행 중 임시 저장입니다. 저장소 접근·용량 오류가 나면 화면에 표시하고, 임시 메모리와 JSON 백업·저장 재시도를 제공합니다. 손상된 저장 데이터를 조용히 덮어쓰지 않고 원본 문자열도 JSON 백업에 담습니다. 저장 실패 기록이 남아 있으면 새 측정을 막아 실수로 임시 기록을 덮어쓰지 않도록 합니다. 임시 저장도 불가능한 환경에서 탭을 닫으면 메모리 데이터는 사라질 수 있으므로 먼저 백업하세요.

### 계산 방법

```text
전체 측정 시간 = 좋은 자세 시간 + 확인 필요 시간 + 인식 불가능 시간
좋은 자세 비율 = 좋은 자세 시간 / (좋은 자세 시간 + 확인 필요 시간) × 100
시간당 알림 = 알림 횟수 / (전체 측정 시간 ÷ 3,600,000)
비율 변화 = 최근 측정의 좋은 자세 비율 − 최초 측정의 좋은 자세 비율  [%p]
```

인식 가능한 시간이 0이면 좋은 자세 비율은 **0%가 아닌 `—`**입니다. 시간당 알림은 인식 불가능 시간을 포함한 전체 활성 측정 시간으로 정규화합니다. 이 정의를 CSV와 화면에 동일하게 사용합니다.

최근 7일·30일은 오늘을 포함한 달력 기간입니다. 이전 기간은 바로 앞의 같은 일수입니다. 기간 평균은 개별 퍼센트의 단순 평균이 아니라 **좋은 자세 시간 합계 ÷ 인식 가능한 시간 합계**로 계산합니다. 주별은 월요일 시작이며, 월별·주별 묶음도 현재 선택한 7일/30일 안의 데이터만 합산합니다. 비율 그래프는 기록이 없거나 전부 미인식인 날짜를 연결하지 않습니다. 그래프 점의 설명에 측정 시간을 표시하며 통계의 수치 표도 제공합니다.

최초/최근은 보관 중인 기록의 시작 시각으로 정렬합니다. 두 기록 모두 인식 가능한 시간이 1분 이상이어야 변화 수치와 추세를 제공합니다. 짧은 기록의 원래 비율은 볼 수 있지만 신뢰할 비교로 표현하지 않습니다. 오래된 기록을 삭제하면 보관된 기록 중 가장 이른 것이 새 ‘최초’가 됩니다.

개별 삭제와 전체 삭제는 앱 안에서 삭제 대상을 확인한 뒤 실행합니다. 보관 기간은 전체, 30일, 90일, 1년으로 정할 수 있습니다. 오래된 기록이 있으면 삭제 전 확인을 받으며, 기간 경계에 걸친 한 측정은 전체를 남깁니다. 자동으로 여러 기기 사이에 동기화하거나 영상을 저장하지 않습니다.

### 내보내기

날짜별 CSV는 날짜, 측정 횟수, 상태별 시간, 좋은 자세 비율, 알림과 시간당 알림을 포함합니다. 측정별 CSV는 시작·종료, 모델 조건과 알림 시각도 포함합니다. 한글 Excel 호환성을 위해 UTF-8 BOM을 넣으며, 쉼표·따옴표를 이스케이프하고 수식으로 오인될 수 있는 문자열을 보호합니다. JSON은 기록·설정·저장 실패 기록·현재 임시 기록·저장소 원본을 포함합니다. JSON 복원은 ID별로 병합하며 현재 설정은 유지합니다.

## 8. 테스트 절차 및 확인 범위

### 이번에 확인한 항목

- JavaScript 구문 및 HTML ID 참조 검사 통과
- 실제 기본 모델 메타데이터 확인 및 브라우저에서 모델 다운로드·클래스 로딩 성공: `Class 1` 1개
- 시간·상태 안정화·연속 알림·자정 분할·일별 합산·이전 기간·비율 분모·저장 실패/재시도/중복 방지·CSV 이스케이프·원문 시리얼 및 펌웨어 분기 등의 **모의 검사 25개 통과**
- 브라우저 6개 화면·메뉴·빈 기록·통계 기간 전환 및 알림 시간·테마 설정의 저장/복원 확인

이 항목은 **실제 웹캠 추론, 실제 마이크로비트 USB/LED, MakeCode 컴파일·V1.5 업로드를 검증했다는 뜻이 아닙니다.** 센서·장치 동작과 실제 모델의 분류 품질은 아래 순서로 확인해야 합니다. Netlify에는 실제 배포하지 않았습니다.

## 9. 오류 해결 방법

| 증상 | 확인·해결 |
|---|---|
| 모델을 불러오지 못함 | 공개 HTTPS 폴더 URL인지, `model.json`과 `metadata.json`이 있는지, Pose Model인지 확인. 학교 네트워크에서 jsDelivr·Google 모델 다운로드가 차단되는지도 확인 |
| 화면은 뜨지만 카메라가 안 됨 | Chrome에서 HTTPS 또는 localhost로 열기. 주소창 사이트 권한에서 카메라 허용. OS 개인정보 설정과 다른 화상 앱 점유 확인 |
| 카메라 선택 후 시작 실패 | 제거된 장치일 수 있음. 목록 새로고침 → 기본 카메라로 변경 |
| 확률이 항상 100% 근처 | 한 클래스 모델인지 확인. 비교용 클래스를 충분히 학습. 앱은 한 클래스 모델의 판정을 제한함 |
| 계속 인식 불가능 | 단일 클래스인지 확인. 머리·양쪽 어깨·상체가 프레임 안에 보이도록 뒤로 이동. 조명·가림·너무 작은 어깨 폭 확인 |
| 알림이 발생하지 않음 | 알림이 켜져 있는지, 확인 필요 상태가 중간 미인식 없이 기준 시간 동안 연속되는지 확인. 한 구간 1회 제한은 좋은 자세로 돌아와야 초기화 |
| 소리가 안 남 | 소리 설정과 기기 음량 확인. ‘소리 테스트’ 클릭으로 브라우저 오디오 활성화. 화면 알림은 소리와 독립적으로 동작 |
| Web Serial 미지원 | 데스크톱 Chrome 사용. 모바일·Safari·일부 내장 브라우저는 지원하지 않을 수 있음. 카메라·저장 기능과 별개 |
| USB 포트가 안 보임 | 데이터 케이블, MICROBIT 드라이브, OS 장치 인식 확인. 필요하면 마이크로비트 공식 지원의 펌웨어·드라이버 안내 확인 |
| 포트 열기 실패 | MakeCode 연결·시리얼 모니터·다른 프로그램 종료. 연결 해제 후 다시 연결 |
| 연결됐지만 LED가 안 바뀜 | 동봉된 프레임 프로토콜의 MakeCode 코드인지 확인. 115200bps, LF 구분, LED 알림 켬, 송수신 ACK 확인. 한 클래스 모델은 자동으로 좋은 자세를 보내지 않음 |
| 클래스 전송 제한 | 줄바꿈 또는 UTF-8 96바이트 초과 확인. 앱은 원문을 바꾸지 않음. 필요하면 Teachable Machine에서 이름을 명시적으로 정리한 뒤 다시 내보내기 |
| 기록 저장 실패 | localStorage 차단·용량 부족·비공개 모드 확인. 먼저 JSON 백업 후 오래된 기록 정리, 저장 재시도. 실패 기록이 있을 때 탭을 닫지 않기 |
| 다른 주소에서 기록이 없음 | 저장소는 브라우저·사이트 주소별로 분리됨. 기존 주소에서 JSON 백업 → 새 주소에서 복원 |
| 비교가 `—`로 나옴 | 두 번 이상 측정하고 최초/최근 각각 인식 가능한 시간을 1분 이상 확보. 단일 클래스 모델의 미인식만으로는 비교 불가 |
| 다른 탭에서 측정 중이라고 표시 | 해당 탭에서 측정 종료. 한 탭만 카메라 측정을 실행하도록 한 보호 기능 |
